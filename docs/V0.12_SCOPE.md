# Eidome v0.12 — Anatomy navigation UX

## Why

Eidome exists to help a person understand their body, why it moves the way it does, and what to improve next. Anatomy is useful only when a person can find a structure, understand what the model is showing, and move from reference anatomy toward movement meaning.

## Included

- A searchable browser generated from named nodes in the bundled anatomy model
- Category filters derived from the source structure names
- Side and tissue labels for every listed structure
- Selection and isolation directly from the structure list
- A visible count of discoverable structures in each layer
- Honest copy explaining that one selectable mesh can represent fascia or another grouped surface
- Existing tap selection, camera preservation, fascia reveal and full-layer restoration

## Not included

- New or re-segmented anatomy assets
- Claims that every visible surface is one muscle
- Medical diagnosis or scan-level accuracy
- Exercise programming, workouts or live coaching; those belong to Forge
- HealthKit, accounts, cloud sync or video movement analysis

## Acceptance checks

1. Muscles and Skeleton each publish a non-empty searchable catalog when their bundled USDZ layer loads.
2. Search matches structure name, side and category.
3. Selecting a browser result closes the browser, selects the correct structure and isolates it.
4. Direct 3D tapping still selects structures.
5. Fascia can still be hidden to reveal deeper geometry and restored afterward.
6. Switching layers does not show stale structures from the previous layer.
7. Customer-facing copy distinguishes reference anatomy from measured personal data.
8. Review-readiness validation expects marketing version 0.0.12 and build 12.
