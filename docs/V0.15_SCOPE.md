# Eidome v0.15 — Persistent 3D Workspace

## Why

The explorer should behave like a personal workspace rather than returning to a generic camera every time a user changes context or relaunches the app.

## App Store user outcome

Each profile remembers a useful, safe view of Body, Muscles, Skeleton, and Joints. The user can reset any layer to a deterministic default at any time.

## Release scope

- Persist camera transform, orbit target, field of view, and orthographic scale per profile and layer
- Restore safe state after layer changes, navigation, backgrounding, and relaunch
- Validate persisted values before applying them
- Keep the existing accessible Reset view action
- Remove saved views with profile deletion and Delete All Data
- Preserve the v0.12–v0.14 anatomy navigation, education, licensing, and why-first experience
- Supply complete Guideline 2.1 App Review clarification

## Acceptance criteria

- [x] Rotate and zoom a layer, visit another layer, and return to the same view
- [x] Background or relaunch the app and restore the last safe view
- [x] Store independent camera state for Body, Muscles, Skeleton, and Joints
- [x] Keep camera state isolated by profile
- [x] Reject corrupt, non-finite, or out-of-bounds saved state
- [x] Reset view removes the saved value and restores the deterministic default
- [x] Profile deletion removes that profile’s camera state
- [x] Delete All Data removes all camera state
- [ ] Confirm the complete behavior on a physical iPhone
- [ ] Capture the App Review demonstration video on that physical device

## Trust and product boundary

This release changes navigation state only. It does not alter anatomy, personalize internal structures, or imply greater model accuracy.
